# 020 — CIR

CIR is chiero's intermediate representation and the **contract boundary** of the whole
project ([001 §3](001-architecture.md)). `chiero-cir` depends on no frontend crate, ships
a textual format with both a printer and a parser, and is therefore the language in which
the symbolic core is specified, written and tested **before the C frontend exists**.

Read this document as the definition of what the engine consumes. `chiero-lower` is
obliged to produce it; nothing in [021](021-memory-model.md)–[024](024-environment-models.md)
may reach past it.

## 1. Design commitments

1. **Unstructured CFG.** Basic blocks with explicit terminators. No loops, no `if` nodes.
   C's `goto`, `switch` fallthrough and `break`/`continue` all become edges.
2. **Three-address.** Every `RValue` has at most one operation and operands are atoms
   (`ValueId` or `Const`). No nested expression trees. Symbolic evaluation of an
   instruction is therefore a single, total, side-effect-free step.
3. **Not SSA.** Locals are `alloca` + `load`/`store`, like LLVM at `-O0`. `ValueId`s are
   single-assignment *temporaries* within a function, but program variables live in
   memory. This makes lowering trivial and pushes the difficulty into the memory model,
   which is where we want it: the memory model has to be strong for C anyway (address-of,
   unions, type punning, negative offsets), so making it also carry local variables costs
   nothing and saves a whole phi-placement algorithm.
4. **No aggregate values.** Structs, unions and arrays exist only in memory. There is no
   `ValueId` of aggregate type; aggregate assignment is `CopyMem`. Scalars are integers,
   floats, pointers and vectors.
5. **Every instruction carries a `Span`.** Every block carries the set of gcov lines it
   is attributable to. Provenance is not optional metadata that can be dropped in a
   release build — it is the product.
6. **Explicit everything.** Every conversion is a `Cast`; every integer op names its
   width and signedness; no implicit promotion survives lowering ([014 §5](014-semantics-and-types.md)).

`mem2reg` is an optional, later, *opt-in* pass (§9). The engine must be correct without it.

## 2. Types

CIR types are lowered: no typedefs, no qualifiers, no field names.

```rust
pub enum CTy {
    Void,
    Int(u32),                        // bit width; _Bool is Int(1), __int128 is Int(128)
    Float(FloatKind),                // F32 | F64 | X87_80
    Ptr,                             // opaque: pointers are address-sized, untyped
    Vector { elem: Box<CTy>, lanes: u32 },
}
```

**Pointers are untyped in CIR.** The pointee type lives on the memory operation
(`Load { ty }`, `Store { ty }`), not on the pointer. C's type punning, `void*` and
`char*` aliasing make a typed-pointer IR a source of lies; the access type at the point
of access is the only thing that is actually true.

Signedness is **not** a property of `Int` — it is a property of the *operation*
(`SDiv` vs `UDiv`, `ICmp { signed }`, `Cast::SExt` vs `Cast::ZExt`). This mirrors what
the solver's bitvector sort can express and eliminates a class of lowering bugs where a
value's declared signedness disagrees with the operation applied to it.

Aggregate layout is resolved by `chiero-sema` and appears in CIR only as byte sizes,
offsets and alignments. A `StructLayoutId` may be attached to an `AccessPath` (§4.4) for
reporting, but no analysis may depend on it for semantics.

## 3. Program structure

```rust
pub struct Module {
    pub funcs:   Vec<Function>,        // indexed by FuncId
    pub globals: Vec<Global>,          // indexed by GlobalId
    pub target:  TargetConfig,         // from 014 §1; recorded, never re-derived
    pub source_map: Option<Arc<SourceMap>>,   // None for hand-written .cir
}

pub struct Global {
    pub id: GlobalId, pub name: Symbol,
    pub size: u64, pub align: u64,
    pub init: GlobalInit,              // Zero | Bytes(Vec<u8>) | Relocs(Vec<Reloc>) | Extern
    pub is_const: bool, pub linkage: Linkage,
    pub span: Span,
}

pub struct Function {
    pub id: FuncId, pub name: Symbol,
    pub params: Vec<Param>,            // ValueId + CTy, in declaration order
    pub ret: CTy,
    pub variadic: bool,
    pub allocas: Vec<AllocaDecl>,
    pub blocks: Vec<Block>,            // indexed by BlockId
    pub entry: BlockId,
    pub attrs: FnAttrs,                // noreturn, no_side_effects, ctor/dtor, march_variant
    pub body: Body,                    // Defined | Declared (extern) | Modeled(ModelId)
    pub span: Span,
}

pub struct AllocaDecl {
    pub id: AllocaId, pub ty: CTy,     // element type
    pub count: SizeExpr,               // Const(u64) | Dynamic(ValueId) — VLA / alloca()
    pub align: u64,
    pub name: Option<Symbol>,          // for reporting; not semantic
    pub span: Span,
}

pub struct Block {
    pub id: BlockId,
    pub insts: Vec<Inst>,
    pub term: Terminator,
    /// gcov attributes counts to these lines. Computed via SourceMap::expansion_loc,
    /// never via spelling_loc — see 010 §3.1 and 030 §5.
    pub gcov_lines: SmallVec<[u32; 4]>,
    pub span: Span,
}
```

`Body::Declared` functions have no blocks: a call to one is resolved by
[024](024-environment-models.md) or havocs its pointer arguments and returns a fresh
symbol with `Fidelity::Approximated`.

`FnAttrs::march_variant` records VPP's `CLIB_MARCH_VARIANT` ([060](060-vpp-integration.md)):
one C source can produce several `Function`s that differ only by variant, and they must
not be conflated.

## 4. Instructions

```rust
pub struct Inst { pub kind: InstKind, pub span: Span }

pub enum InstKind {
    Assign  { dst: ValueId, rv: RValue },
    Store   { addr: Operand, val: Operand, ty: CTy, align: u64, vol: Volatility },
    StoreBits { addr: Operand, val: Operand, unit: CTy, bits: BitRange, align: u64 },
    CopyMem { dst: Operand, src: Operand, size: Operand, align: u64, overlap: Overlap },
    SetMem  { dst: Operand, byte: Operand, size: Operand },
    Call    { dst: Option<ValueId>, callee: Callee, args: Vec<Operand>, conv: CallConv },
    Opaque  { writes: Vec<OpaqueWrite>, reads: Vec<Operand>, why: OpaqueReason },
    Marker  (MarkerKind),
}

pub enum Callee { Direct(FuncId), Indirect(Operand) }

pub enum Operand { Value(ValueId), Const(Const) }

pub enum Const {
    Int { bits: u32, val: i128 },      // stored sign-extended; interpretation is per-op
    Float(FloatKind, u64),             // raw bits, so NaN payloads survive round-trip
    Null,
    GlobalAddr { g: GlobalId, off: i64 },
    FuncAddr(FuncId),
    Undef(CTy),
}
```

### 4.1 RValue

```rust
pub enum RValue {
    Use   (Operand),
    Load  { addr: Operand, ty: CTy, align: u64, vol: Volatility },
    LoadBits { addr: Operand, unit: CTy, bits: BitRange, signed: bool, align: u64 },
    Bin   { op: BinOp, a: Operand, b: Operand, ty: CTy },
    Un    { op: UnOp,  a: Operand, ty: CTy },
    Cmp   { op: CmpOp, a: Operand, b: Operand, ty: CTy },   // result is Int(1)
    Cast  { kind: CastKind, a: Operand, from: CTy, to: CTy },
    Select{ cond: Operand, t: Operand, f: Operand },
    PtrAdd{ base: Operand, off: Operand, path: Option<AccessPath> },
    AddrOfLocal  { alloca: AllocaId },
    AddrOfGlobal { g: GlobalId },
    AddrOfFunc   (FuncId),
    VaArg { list: Operand, ty: CTy },
    Fresh { ty: CTy, why: FreshReason },        // symbolic input; see 021 §6
}

pub enum BinOp {
    Add, Sub, Mul, UDiv, SDiv, URem, SRem,
    And, Or, Xor, Shl, LShr, AShr,
    FAdd, FSub, FMul, FDiv, FRem,
    PtrAdd,                                     // reserved: see note
    PtrDiff { elem_size: u64 },
}
pub enum CmpOp { Eq, Ne, ULt, ULe, UGt, UGe, SLt, SLe, SGt, SGe, FOEq, FOLt, FULt, /* … */ }
pub enum CastKind { Trunc, ZExt, SExt, FpTrunc, FpExt, FpToUi, FpToSi, UiToFp, SiToFp,
                    PtrToInt, IntToPtr, Bitcast }
```

**`PtrAdd` is a distinct `RValue`, not integer `Add`.** Pointer arithmetic must stay
distinguishable from integer arithmetic so that the memory model can preserve *provenance*
(the result stays anchored to `base`'s object, [021 §3](021-memory-model.md)) and so the
OOB checker can fire on the arithmetic rather than only on the eventual dereference.
Lowering emits `PtrToInt` explicitly when C code genuinely converts.

Arithmetic on `Int(N)` is **two's-complement wrapping** at the CIR level. Signed overflow
is UB in C, but CIR is not the place to encode UB as unpredictability: the semantics are
defined and total, and a `Checker` observes the overflow event and reports it
([040](040-defect-checkers.md)). This separation — defined IR semantics, UB reported as
findings — is deliberate and applies to shifts (`Shl` by ≥ width yields 0 and reports)
and division (`SDiv` by 0 reports and yields `Undef`).

`Fresh` is how symbolic inputs enter a program with no frontend: a hand-written `.cir`
test can say `%x = fresh i32 "input"`. It is also what lazy initialization
([021 §6](021-memory-model.md)) materializes.

### 4.2 Volatility and atomics

```rust
pub enum Volatility { Normal, Volatile }
```

A `Volatile` load never reads the memory model's stored bytes: it produces a `Fresh`
value each time and is never cached, CSE'd or reordered by any pass. A `Volatile` store
is an observable event recorded on the path. VPP's device-register and counter code
depends on this.

v1 treats C11 atomics as their non-atomic equivalents plus a recorded
`Fidelity::Approximated` note, consistent with the single-threaded non-goal
([000](000-overview.md)). The ordering argument is preserved in the IR so that a future
concurrency mode does not need a format change.

### 4.3 Opaque

Inline `asm` (31 VPP files) and any construct chiero parses but refuses to model:

```rust
pub struct OpaqueWrite { pub addr: Operand, pub size: Operand }   // clobbered region
pub enum OpaqueReason { InlineAsm, UnmodeledBuiltin(Symbol), UnsupportedConstruct(&'static str) }
```

`Opaque` havocs exactly its declared writes and forces `Fidelity::Approximated` on every
result derived from the path. It must never be silently equivalent to a no-op — a no-op
would let a checker "prove" something about code it did not understand.

### 4.4 Markers and access paths

```rust
pub enum MarkerKind {
    Line(u32),                 // gcov line boundary (030)
    SeqPoint,                  // C sequence point (§7)
    Scope(ScopeEvent),         // Enter/Exit — drives stack-object lifetime (021 §4)
    Assume(Operand),           // path constraint injected by a model or annotation
    Label(Symbol),             // preserved C label, for reporting and replay
}

pub struct AccessPath { pub root: PathRoot, pub steps: SmallVec<[PathStep; 4]> }
pub enum PathStep {
    Field { name: Symbol, off: u64 },
    /// Which member of a union this access viewed the bytes through, and the record it
    /// belongs to. Purely for reporting — see §4.5.
    UnionMember { name: Symbol, off: u64, view: Symbol },
    Bits { name: Symbol, bits: BitRange },
    Index(Operand),
    Deref,
}
```

`AccessPath` is **reporting-only** — it makes a finding read `p->adj[3].counter`, or
`b->opaque as ip4_rewrite_t.adj_index`, instead of `*(i64*)(%7 + 24)`. No analysis may
branch on it. `Scope` markers are semantic: they bound the lifetime of stack objects,
which is what makes use-after-scope detectable.

## 4.5 Unions, punning and layout-dependent access

VPP is saturated with layout-dependent union idioms, and they are not incidental — they
are the ABI. `ip4_address_t` is `union { u32 as_u32; u8 as_u8[4]; }`; `vlib_buffer_t`
carries `u32 opaque[10]` that each graph node reinterprets as its own struct;
`u32x4`/`u8x16` are the same 16 bytes viewed two ways; several headers declare bitfields
whose order flips under `#if CLIB_ARCH_IS_BIG_ENDIAN`. Any IR that models a union as a
tagged value with an "active member" will be wrong on the first packet.

CIR handles all of it, and the handling is a consequence of three commitments already
made rather than a special case:

1. **No aggregate values** (§1.4) — a union has no value form. It exists only as bytes in
   a `MemObject`, so there is nothing to tag.
2. **Untyped pointers** (§2) — the access type lives on the access. `&u` is one pointer;
   `u.as_u32` and `u.as_u8[2]` are `Load i32` and `Load i8` at offsets 0 and 2 from it.
   No conversion, no cast node, no active-member state.
3. **Byte-level memory with no strict-aliasing assumption**
   ([021 §3](021-memory-model.md)) — writing `as_u32` and reading `as_u8[2]` returns byte
   2 of what was written, exactly, including when it is symbolic.

Consequences worth stating explicitly, because they are the ones that get implemented
wrong:

- **Union member access is offset arithmetic**, identical in form to struct field access;
  the member's offset is 0 for every non-bitfield member. Lowering emits `PtrAdd` plus a
  `UnionMember` path step for reporting.
- **Reading a member other than the last one written is legal and produces no finding.**
  C89/C99 call this undefined; gcc defines it; VPP depends on it. chiero follows gcc.
  A `union-pun` checker exists but is **off by default** — enabling it on VPP would emit
  tens of thousands of findings about code that is working as designed.
- **Partial overwrite is exact.** Writing `as_u8[1] = 0xFF` after `as_u32 = x` leaves a
  value whose bytes are `x[0], 0xFF, x[2], x[3]` — a `Concat` of three symbolic bytes and
  one constant, not a havoc of the whole word ([021 §3](021-memory-model.md)).
- **Vector/scalar views** are `Bitcast` between `Vector { elem, lanes }` and an `Int` of
  the same total width when the value is in a register, and plain re-typed loads when it
  is in memory. Both must agree, and contract 22 pins that.
- **`container_of` / negative-offset idioms** are the same mechanism as the vppinfra
  vector header ([021 §2](021-memory-model.md)): a `PtrAdd` by a negative constant that
  stays anchored to the enclosing object. Because provenance survives `PtrAdd`, the
  resulting pointer is bounds-checkable against the *whole* enclosing object.
- **Endianness-conditional layouts** are resolved before CIR: the two bitfield orderings
  live behind `#if`, so they are two different `ConfigId`s
  ([012 §3.3](012-preprocessor.md)) producing two different `RecordLayout`s
  ([014 §3](014-semantics-and-types.md)). CIR sees whichever one the configuration
  selected, and the `ConfigId` is recorded on every result.

### 4.5.1 Bitfields

Bitfields are the one case that byte-granular `Load`/`Store` cannot express correctly, so
CIR has dedicated forms:

```rust
pub struct BitRange { pub off: u32, pub width: u32 }   // bit offset within `unit`, width in bits
```

`LoadBits { addr, unit, bits, signed }` reads the `unit`-sized storage unit at `addr` and
extracts `bits`, sign- or zero-extending per the declared type. `StoreBits` is a
read-modify-write of only those bits.

Two reasons this is a distinct instruction rather than sugar for load/shift/mask/store:

- **Uninitialized-read accuracy.** Lowering `f.a` (bits 0..3) to a full-byte load would
  read the bits of `f.b` (bits 3..8). If `b` was never written, a byte-granular
  initialization mask reports a spurious uninitialized read on every access to `a`. With
  `LoadBits`, only bits 0..3 are consulted — which requires the memory model to track
  initialization at bit granularity for partially-written bytes
  ([021 §3.1](021-memory-model.md)).
- **Clobber accuracy.** `StoreBits` must not disturb neighbouring bitfields' *symbolic*
  bytes, and expressing that as an explicit RMW in CIR would make every pass responsible
  for recognizing the idiom in order not to break it.

Bit ordering within the unit comes from `TargetConfig::bitfield_abi`, computed once in
[014 §3](014-semantics-and-types.md). CIR stores the already-resolved `BitRange` and never
re-derives it — one place to be wrong is better than two.

## 5. Terminators

```rust
pub enum Terminator {
    Goto  (BlockId),
    Br    { cond: Operand, t: BlockId, f: BlockId },
    Switch{ scrut: Operand, ty: CTy, cases: Vec<(i128, BlockId)>, default: BlockId },
    Return(Option<Operand>),
    IndirectGoto { addr: Operand, targets: Vec<BlockId> },   // GNU computed goto
    Unreachable(UnreachableReason),
}
```

`Switch` cases are **sorted and deduplicated** by the verifier so that path exploration
order is deterministic ([001 §5](001-architecture.md)). GNU case ranges (7 VPP files) are
expanded to individual cases when the range is small (≤ 64 values) and to a guarded chain
otherwise; the threshold is a documented constant, not a heuristic that varies by build.

`Unreachable` carries why (`AfterNoreturn`, `ExhaustiveSwitch`, `BuiltinUnreachable`,
`LoweringGap`). `LoweringGap` is not an optimization licence: reaching it is a
`Fidelity::Unknown` result and a diagnostic, never "this path is infeasible".

## 6. Textual format

The textual format is normative, not a debugging convenience: core test fixtures are
`.cir` files, and the printer/parser round-trip is a contract.

```
target x86_64-unknown-linux-gnu

global @counts : size 32 align 8 = zero
func @vec_len_minus_1(%v: ptr) -> i32 {
  alloca %slot : i32 x 1 align 4 "n"          ; @vec_len.c:12
entry:
  .line 12
  %len_p = ptradd %v, -8i64                    ; header at negative offset (021 §2)
  %len   = load i32, %len_p align 4
  %n     = sub i32 %len, 1i32
  store i32 %n -> %slot align 4
  %c     = cmp slt i32 %n, 0i32
  br %c, bb_bad, bb_ok
bb_ok:
  .line 14
  ret %n
bb_bad:
  .line 15
  unreachable builtin
}
```

Rules:
- Round-trip is exact for everything semantic. `print(parse(s)) == s` for canonical input;
  `parse(print(m))` is structurally equal to `m` for every module.
- Spans are optional in the source text and printed as `; file:line` comments. A `.cir`
  file with no spans is legal and gets `Span::DUMMY` with `ExpnCtx::ROOT` — this is what
  makes hand-written core tests cheap.
- Unknown directives are a hard parse error. Silent tolerance in a test-fixture format
  produces tests that pass by not testing anything.

## 7. Evaluation order and sequence points

C leaves the evaluation order of subexpressions unspecified. CIR is a *specific* order:
lowering emits operands **left to right**, and that order is part of the specification so
results are reproducible.

Because a specific order can hide a real bug, lowering additionally emits `SeqPoint`
markers and sets `Function::attrs.order_sensitive` when a full expression contains two
unsequenced accesses to the same object with at least one write (`i = i++`,
`f(g(), h())` where both mutate a shared global). An **order-dependence checker**
([040](040-defect-checkers.md)) runs off exactly this signal. Emitting a canonical order
without also flagging the dependence would silently endorse one of several legal
behaviours, so the two are specified together.

## 8. Verifier

`chiero_cir::verify(&Module) -> Vec<VerifyError>` runs before execution, always, including
on hand-written fixtures. Rules:

1. Every `ValueId` is assigned exactly once and dominates every use.
2. Every `BlockId` referenced by a terminator exists in the same function.
3. Every block is reachable from `entry`, or is reported as dead (a warning, not an error;
   unreachable C code exists).
4. Every block ends in exactly one terminator; no terminator appears mid-block.
5. Operand widths match the operation's declared `ty`; `Cmp` yields `Int(1)`; `Cast`
   widths are consistent with the kind (`Trunc` narrows, `ZExt`/`SExt` widen strictly).
6. `PtrAdd`'s base is pointer-typed; `Load`/`Store`/`CopyMem` addresses are pointer-typed.
7. Alignments are powers of two and non-zero.
8. `Switch` cases are unique; `default` exists.
9. `entry` has no predecessors (lowering must insert a preheader if C control flow would
   create one).
10. Function bodies with `Body::Declared` have zero blocks; `Body::Defined` has ≥ 1.
11. `BitRange::width ≥ 1` and `off + width ≤ bit_width(unit)`; `LoadBits`/`StoreBits`
    `unit` is an `Int`.

A module that fails verification is never executed. Verification is O(size) and runs in
every test.

## 9. Optional passes

Passes are opt-in, off by default, and each must be **observationally transparent**: for
the same entry state, the set of reported findings and their concrete counterexamples is
unchanged, only performance differs. Each ships with a differential test that runs the
corpus with and without it and diffs the findings.

- `mem2reg` — promote non-address-taken allocas to `ValueId`s (inserts real phis; the IR
  grows a `Phi` instruction that only this pass may emit).
- `simplify_cfg` — merge blocks with a single predecessor/successor, drop empty blocks.
  Must preserve `gcov_lines` by union, or coverage correlation breaks.
- `const_fold` — fold `Const`-only `RValue`s.

No pass may drop a `Marker`, merge two blocks with different `Volatile` accesses,
discard `Span`s, or widen a `LoadBits`/`StoreBits` into a byte-granular access (§4.5.1).

## 10. Testable contracts

1. `parse(print(m))` is structurally equal to `m` for every module in `tests/corpus/cir/`.
2. `print(parse(s)) == s` for every canonical `.cir` fixture (byte-exact).
3. A `.cir` file with an unknown directive fails to parse with a diagnostic naming the
   line.
4. `verify` rejects: a `ValueId` assigned twice; a use not dominated by its definition; a
   branch to a nonexistent block; a mid-block terminator; a `Cmp` declared as `Int(32)`;
   a `Trunc` from `Int(8)` to `Int(32)`; an alignment of 3; a duplicate `Switch` case; a
   `Body::Declared` function with a block. Each produces exactly one `VerifyError`
   identifying the offending instruction's `Span`.
5. `verify` accepts every fixture in `tests/corpus/cir/` and reports zero errors.
6. `chiero-cir`'s `Cargo.toml` dependency closure contains no frontend crate
   (mechanically checked; duplicates [001 §7](001-architecture.md) contract 3 because it
   is the rule most likely to be violated under pressure).
7. `Int(32)` `Add` of `0x7FFFFFFF` and `1` yields `0x80000000` (wrapping, defined), and
   emits exactly one signed-overflow event.
8. `Shl` of `Int(32)` by 32 yields 0 and emits exactly one shift-UB event.
9. `SDiv` by `0` yields `Undef` and emits exactly one div-by-zero event; execution of the
   path stops.
10. A `Volatile` load executed twice at the same address with no intervening store yields
    two distinct symbols; a `Normal` load yields the same value.
11. `Opaque` with a declared write of `[p, p+8)` invalidates exactly those 8 bytes and
    leaves `[p+8, …)` intact, and marks the state `Fidelity::Approximated`.
12. Lowering `s1 = s2` for a 40-byte struct emits one `CopyMem` of size 40, not 10 loads
    and stores.
13. A `Switch` printed twice from the same module produces identical case order.
14. GNU case range `case 1 ... 4:` with a span of 4 expands to 4 cases; a span of 10 000
    expands to a guarded chain, and both produce identical execution results on the corpus.
15. Every `Inst` in a module lowered from C has a non-dummy `Span`, and every `Block` has
    a non-empty `gcov_lines` unless it is compiler-generated (verified over the corpus).
16. Running `mem2reg` over the corpus leaves the set of findings and counterexamples
    byte-identical to running without it.
17. `simplify_cfg` preserves the union of `gcov_lines` across merged blocks.
18. A function containing `i = i++` sets `order_sensitive` and produces exactly one
    order-dependence finding; `i = i + 1` sets neither.

### Unions, punning and bitfields (§4.5)

19. `union { u32 as_u32; u8 as_u8[4]; } u;` — storing `0x11223344` to `as_u32` then
    loading `as_u8[2]` yields `0x22` under the little-endian target and `0x33` under a
    big-endian one. No cast node and no active-member state appear in the CIR.
20. The reverse order — four `as_u8` stores then one `as_u32` load — yields the
    corresponding concatenation, and produces **zero** findings with the default checker
    set.
21. Storing a *symbolic* `u32` to `as_u32` then overwriting `as_u8[1]` with a constant,
    then loading `as_u32`, yields a term equal to a `Concat` of three extracted symbolic
    bytes and the constant — verified by asserting equality with the hand-built term, not
    by string comparison.
22. For a 16-byte union viewed as `u32x4` and as `u8x16`: a lane-3 vector store followed
    by byte loads at offsets 12..16 agrees with the scalar path, both in register form
    (`Bitcast`) and through memory.
23. A 40-byte `opaque[10]` region written through one struct view and read through a
    different struct view of the same size returns the written bytes exactly, and the
    finding text for an OOB access through the second view names the second view's member
    (`UnionMember { view }`).
24. `struct { u32 a:3; u32 b:5; }` — writing only `a` and then reading `a` produces no
    uninitialized-read finding, while reading `b` produces exactly one. (This is the
    contract that byte-granular lowering fails.)
25. `StoreBits` to `a` leaves every bit of `b` unchanged, including when `b`'s bits are
    symbolic — checked by term equality before and after.
26. `LoadBits` with `signed: true` over `a:3` holding `0b111` yields `-1` at `Int(32)`;
    with `signed: false` it yields `7`.
27. `verify` rejects a `BitRange` with `off + width` exceeding the unit width, and one
    with `width == 0`.
28. A `container_of`-style `PtrAdd` by `-offsetof(S, member)` produces a pointer whose
    `base` is the enclosing object, and a subsequent full-struct read is in bounds.
29. The `union-pun` checker is off in the default checker set; enabling it on a corpus
    punning fixture produces findings, and the default run on the same fixture produces
    none.
30. The same union source compiled under a big-endian `ConfigId` and a little-endian one
    produces two modules with different `BitRange`s, and each result records its
    `ConfigId`.
